# open-pstack

Track all durable work in this repository's GitHub Issues. Do not create a parallel Linear queue. Read `UPSTREAM.md` before changing upstream-derived content.

Cursor's `cursor/plugins/pstack` tree is the content upstream. Keep one shared skill tree for Claude Code and Codex; adapt harness primitives at the existing mapping boundaries instead of forking skills or adding compatibility layers. The parent harness resolves provider routing once. Children do not detect or reroute themselves.

Before opening a pull request, run the Bun tests, strict typecheck, static invariants, and plugin validation.

Nothing merges, tags, releases, or rolls out until the exact candidate is installed and the changed behavior passes a live test from the real user surface in every affected harness. Unit tests, validators, source inspection, and self-reports do not satisfy this gate. Record the installed version, surface, action, and observed result in the pull request template. A pull request without that evidence remains a draft.

For Open Pstack PRs, use the shared repository-local `.claude/skills/verify-open-pstack/` skill (Codex: `.agents/skills/verify-open-pstack`). Run its independent Bun tests/typecheck separately from the shipped package. The trusted parent validates the explicitly selected caam 0.1.22 vault identities, copies only disposable Claude `.credentials.json` and Codex `auth.json` into run-owned config roots, records account emails, and deletes copied credentials in final cleanup without vault activation/writeback. GitHub publication stays exclusively in the trusted parent. Setup uses fixture homes only; project self-test uses planned `doctor --candidate` without vault probing. Require operator-Mac `bun test scripts/isolation.test.ts`, real-filesystem sentinel denials, no Keychain dialog, and observable authenticated API requests from both native sessions; unavailable implementation or unproven enforcement blocks the run. Builders do not publish the gate, queue, or merge; new delivery PRs start draft, but already-ready PR #111 must not be re-drafted during review remediation. The helper requires exact-head installed-source provenance, operator-reviewed native evidence, revalidated artifact hashes, and a populated/read-back PR `Live evidence:` block before gate/readiness publication. Every new head, including a queue-created head, needs a fresh run after required reviews pass; never hand-post a replacement status. Preserve redacted evidence and record credential-cleanup outcome.
